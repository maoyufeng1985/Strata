# q36：K 量化的 FP16 融合反量化 —— 三个 bug 与更正后的实测（2026-10-24）

**结论先说：上一份文档的数字是错的，"数值 bit-exact" 也是错的。**
更正后，完整专家 **37.64 µs/专家**（int8 MMQ 是 100.50，**快 2.67 倍**），
权重仍然只存 Q4_K/Q5_K，显存不变。

## 0. 错在哪

我之前写的 Q5_K down 探针（`q5down.cu` ~ `q5down4.cu`）算出来的数全是垃圾，
但它自带的"数值检查"每次都打印 `max|diff| = 0.0000e+00`。

**检查为什么是假的**：

```c
hX[i] = (float)((i % 23) - 11) * 0.05f;   // i 是 size_t（无符号）
```

`i % 23 < 11` 时 `0 - 11` 下溢成 1.8e19 → 激活是垃圾 → 点积溢出成 inf →
kernel 输出 NaN → 检查里 `if (d > worst)` 对 NaN 恒假 → `worst` 保持 0 → "通过"。

**三个真 bug**（都在 Q5_K 路径，Q4_K 路径有同类的第三类）：

| # | 位置 | 错法 | 后果 |
|---|---|---|---|
| 1 | qs 读地址 | `ldg32(bp + 48 + 32*c64 + my_byte)`，`my_byte = lane*4` **已经含了 `32*c64`**，又多加一次 | 4 个 64 值组里只有第 0 组对，**3/4 的值全错** |
| 2 | qh（第五位） | 读 `bp + 16 + 32*c64 + my_byte`，但 qh 只有 32 字节；掩码还取了 2 个 bit | 75% 的 lane 读到 qs 数组甚至越过块尾 |
| 3 | d / dmin / scales | 被提到 superblock 循环**外面**了 | 每个 superblock 有自己的 d/dmin/scales，第二个 superblock 一直用第一个的 scale |

**第 4 个问题不是 bug，是精度陷阱**：1024 偏移技巧
`w = __hfma2(1024+q5, d*s, -(1024*d*s + dmin*m))`。
bias 的量级是 `1024*d*s`，而 fp16 在那里的间距正好是 `d*s`（一个量化步长），
**bias 自己就带半个步长的误差**。实测：反量化误差 0.294 步（精确版 0.006 步），
点积相对误差最大 **13.6%**。

改成先把 1024 减掉（`(1024+q5) - 1024` 是精确的，Sterbenz），再 FMA：

```
w = __hfma2(q5, d*s, -dmin*m)
```

## 1. 正确的布局（ggml 源码）

`third_party/llama.cpp/ggml/src/ggml-quants.c`：

- `dequantize_row_q4_K`（第 1529 行）和 `dequantize_row_q5_K`（第 1731 行）
  **结构完全一样**：

```
一个 superblock = 256 个值，分 4 个 64 值组。
组 b 用 qs[32b .. 32b+31] 这 32 个字节：
    低 nibble  -> 值 64b + l        (scale 组 2b,   min 组 2b)
    高 nibble  -> 值 64b + 32 + l   (scale 组 2b+1, min 组 2b+1)
Q5_K 多一个第五位：qh[l] 的第 2b 位给低 nibble，第 2b+1 位给高 nibble。
四个组共用同一批 32 个 qh 字节，只有位号不同。
```

- 块的大小：Q4_K = 144 B（d, dmin, scales[12], qs[128]），
  Q5_K = 176 B（d, dmin, scales[12], qh[32], qs[128]）。

**一个 lane 的分工**：`c64 = lane>>3`（第几个 64 值组），`j4 = (lane&7)*4`（组内第几个字节）。

```
低 nibble 的 4 个值  -> K 下标 64*c64 + j4 + {0,1,2,3}
高 nibble 的 4 个值  -> K 下标 64*c64 + 32 + j4 + {0,1,2,3}
激活就读这两个位置的各 4 个 half
```

**第五位怎么取**（一个 lop3 都不用）：

```c
// qh[l] 的第 p 位 -> 5-bit 码的第 4 位
((qh4 & (0x01010101u << p)) >> p) * 16u
```

移位把每位拉到字节的 bit 0，乘 16 放到 bit 4；`1*16 = 16 < 256`，不会跨字节进位。

## 2. 实测（P100，sm_60，56 SM，CUDA 12.8）

远端 192.168.1.98，M=16，E=39 专家一次 launch，**频率 1328 MHz**（P0，
`nvidia-smi -i 2` 实测，显存 715 MHz，100% 占用）。

> 频率要看 **nvidia-smi index 2**（PCI 03:00.0，P100）。
> `nvidia-smi -i 0` 是 PCI 01:00.0 的 **P104**，别看错卡。
> 一次进程里的第一次测量会慢约 10%（频率还在爬），下面取稳定值。

**gate/up（Q4_K，N=512，K=2048）**

| 配置 | µs/专家 | TFLOP/s |
|---|---|---|
| **ROWS=16 COLS=8 CH=8 half2** | **11.72** | **2.863** |
| ROWS=16 COLS=8 CH=4 half2 | 12.96 | 2.588 |
| ROWS=16 COLS=4 CH=8 half2 | 13.62 | 2.463 |
| ROWS=8 COLS=8 CH=8 half2 | 14.57 | 2.302 |
| ROWS=16 COLS=8 CH=4 fp32 | 15.66 | 2.142 |

**down（Q5_K，N=2048，K=512）**

| 配置 | µs/专家 | TFLOP/s |
|---|---|---|
| **ROWS=16 COLS=8 CH=8 half2** | **14.20** | **2.363** |
| ROWS=16 COLS=4 CH=8 half2 | 16.76 | 2.002 |
| ROWS=16 COLS=8 CH=4 fp32 | 18.26 | 1.838 |

**完整专家（gate + up + down）= 2 × 11.72 + 14.20 = 37.64 µs/专家**

| 方案 | 每专家 | 相对 int8 |
|---|---|---|
| 引擎现状：int8 MMQ（Q4_K/Q5_K 权重，DP4A int32 累加） | 100.50 µs | 1.00× |
| **融合反量化 + FP16 FMA（更正后）** | **37.64 µs** | **0.37×（快 2.67 倍）** |

（上一份文档写的 31.64 µs / 快 3.2 倍，是基于算错的 kernel，**作废**。）

## 3. 数值

对着 ggml 的 `dequantize_row_q4_K` / `dequantize_row_q5_K`（double 参考）：

| | 点积相对误差（最差） |
|---|---|
| Q4_K | 3.69e-3 |
| Q5_K | 8.28e-2（出现在参考值几乎为 0 的相消 case，绝对误差 0.06） |

half2 累加是安全的：**每个 lane 只累加 K/32 项**（gate/up 是 64 项，down 是 16 项），
不是 K 项。之后 32 个 lane 用 `__hadd2` 树相加。

1024 偏移技巧的对照（同一个 kernel，只换反量化）：

| 反量化 | 权重误差（量化步长） | 点积相对误差 |
|---|---|---|
| 1024 偏移技巧 | 0.294 | 最大 1.36e-1 |
| 先减 1024（**采用**） | 0.006 | 3.69e-3 |

**还没做的**：和 int8 MMQ 路径的 logits 逐行对照。
int8 路径把激活量化成 q8_1（每 32 个元素一个 fp16 scale），误差量级 ~0.4%；
FP16 路径的 0.37% 与它同级，但必须实测对照才能说"没变差"。

## 4. 改动记录（性能）

| 改动 | gate/up | down |
|---|---|---|
| 正确解包（初版） | 15.88 | 19.32 |
| scales 改成 3 次 uint32 载入（原来 12 次单字节） | 13.68 | 16.43 |
| `get_scale_min_k4` 改成无分支（原来 `j<4` 在 warp 内发散）+ 1 次 `ldg128` | **11.72** | **14.20** |

消融（gate/up，去掉 d/dmin/scales 的处理）：**8.94 µs/专家** →
scale 处理占 **2.78 µs = 24%**，是现在最大的单项开销。

## 5. 下一步

| 步 | 内容 | 预期 |
|---|---|---|
| 1 | **scale 处理**：把每个 (列, superblock) 的 (d*s, bias) 预先算好放寄存器或 shared，减少重复的字节提取 | gate/up 11.72 → 约 9.5 |
| 2 | 引擎落地：旗标 `STRATA_Q36_PRIMARY_F16=1`，把 MMQ 的 16 专家分组 + stream-k 套到 FP16 算子上 | 填满 SM |
| 3 | **数值验证**：logits 逐行对照，argmax 一致数 + max\|diff\| | 不合格就不上 |
| 4 | P104 helper：实测 230.93 µs/专家，helper 只能走 int8 | — |

**skip: FP16 权重副本（不需要，Q4 常驻就够，显存不变）；
skip: shared memory 存激活（实测更慢，30.08 vs 17.47，见 `.run/q5down2.cu`）；
skip: 1024 偏移技巧（快 2 µs 但误差 13.6%）；
skip: 全部 8 个 superblock 的 scale 提到寄存器（256 个 half2 = 128 个寄存器，装不下）。**
