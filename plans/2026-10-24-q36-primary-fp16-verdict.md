# q36：「主卡应该走 FP16」—— 复核（2026-10-24）

用户主张：「主卡应该走 FP16」。本文逐条核，结论用实测说话。

**结论：FP16 在这台机器上帮不上主卡。三道独立的门，每道都关着：**
1. **专家权重是量化的**（Q4_K/Q5_K），现有 expert kernel 全是 int8 整数算（`STRATA_DP4A`），
   FP16 GEMM 一行都没接。
2. **FP16 权重更大**（4.00 MiB vs 1.81 MiB，2.21×），要走 PCIe 就更慢。
3. **实测**：专家那种瘦长形状（M=16 行）在 P100 上 FP16 GEMM 要 **90 µs**，
   而搬那份量化权重只要 **313 µs**——**PCIe 是算术的 3.4 倍**。
   就算算力免费，搬权重也回不来。

---

## 1. 硬件：P100 的 FP16 到底有多少

| | 主卡 P100-12GB (GP100) | helper P104-100 (GP104) |
|---|---|---|
| compute cap | 6.0 | 6.1 |
| tensor core | **无** | **无** |
| FP16 峰值（厂商） | 18.7 TF（FP32 的 2 倍，靠 `__half2` FMA） | 3.3 TF |
| SM 数 | **56** | 15 |

**P100 的 18.7 TF 是靠双发射的 `__half2` FMA，不是 tensor core。**
P104 只有 15 个 SM，所以它的 FP16 峰值只有 P100 的 1/6。

**「主卡 FP16 18.7 TF 是 helper 的 2 倍」这个前提本身是对的**（18.7 vs 3.3×3=9.9）。
问题在于专家算不出来。

## 2. 门一：专家权重是量化的，FP16 kernel 一行都没有

gguf 里（`Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf`）：

```
blk.0.ffn_gate_exps.weight   type 12  dims [2048, 512, 256]   <- Q4_K
blk.0.ffn_up_exps.weight     type 12  dims [2048, 512, 256]   <- Q4_K
blk.0.ffn_down_exps.weight   type 13  dims [ 512, 2048, 256]  <- Q5_K
```

三条 expert 路径（复核，2026-10-24）：

| 路径 | kernel | 权重怎么读 | 算术 | sm_60 / sm_61 |
|---|---|---|---|---|
| 主卡 MMQ | `moe_mmq.cu` `Context::run` → `mul_mat_q_case` | 边读边解 K-quant 块 | int8 `STRATA_DP4A` | 4×vmad 回退 / 真 `__dp4a` |
| 主卡 native | `native_expert_grouped`（`iq_kernels.cu:5050`） | 同上 | int8 `STRATA_DP4A` | 同上 |
| helper native | `remote_experts.cpp:553` → 同上 | 同上 | int8 `STRATA_DP4A` | 真 `__dp4a` |

**没有一条走 FP16。** `q36_engine.cu:3122` 附近的 `K::mm` FP16 分支是给 dense 投影
（attention、shared expert 的 `Mat`）用的，专家权重根本不是 `Mat`。

**反量化到 FP16 的 kernel 是现成的**（llama.cpp 依赖里
`ggml/src/ggml-cuda/convert.cu:300` 的 `dequantize_row_q4_K_cuda` /
`:306` 的 `dequantize_row_q5_K_cuda`），`src/kernels/cuda/dequant_bf16.cu` 也有 Q4_K/Q5_K → FP16。
**所以「不能做」不成立 —— 是「没接线，而且接了也不划算」。**

## 3. 门二：FP16 权重更大

| | 每专家字节 | 相对 |
|---|---|---|
| Q4_K gate+up + Q5_K down（现状） | **1.81 MiB**（1,900,544 B） | 1× |
| FP16（3 个矩阵 × 2048 × 512 × 2 B） | **4.00 MiB** | **2.21×** |

显存同理：主卡 VRAM 里放 FP16 专家权重是放量化版的 2.21 倍。
**主卡的 VRAM 现在是紧的**（keep-resident 默认开就是为了腾出 2.86 GiB）。

## 4. 门三：实测 —— PCIe 比算术贵 3.4 倍

探针 `/tmp/fp16exp.cu`（cuBLAS `cublasGemmEx`，CUDA_R_16F / COMPUTE_16F，
专家形状 `[M,2048]×[2048,1024]` + `[M,512]×[512,2048]`，warm 后计时）。

**MEASURED，2026-10-24 远端 192.168.1.98：**

| 卡 | rows | FP16 GEMM | 达到的 TFLOP/s |
|---|---|---|---|
| **P100 (dev0)** | 1 | 80.0 µs | 0.052 |
| **P100** | 4 | 89.2 µs | 0.188 |
| **P100** | **16** | **89.9 µs** | **0.746** |
| **P100** | 64 | 172.4 µs | 1.557 |
| **P100** | 256 | 196.1 µs | 5.475 |
| **P100** | 512 | 267.3 µs | 8.033 |
| **P104 (dev1)** | 16 | 1202.5 µs | 0.056 |
| P104 | 16（sm_61 重编） | 1094.5 µs | 0.061 |

**两个关键读数：**

1. **专家是瘦长形状，M=16** —— 这正是 P100 FP16 最慢的区间。
   **90 µs 只到 0.746 TFLOP/s = 18.7 TF 峰值的 4%。**
   （要到 rows=512 才到 8.0 TF，但专家从来不是 512 行一批。）

2. **P104 上 FP16 GEMM 是 1094 µs，比 P100 慢 12×** —— sm_61 上 cuBLAS 没有
   FP16 GEMM kernel，退回了极慢的路径。（用 sm_60 和 sm_61 两个编译交叉验证过，
   排除编译目标的影响；同一二进制在 P100 上是 91 µs。）

**把这张表和 PCIe 放在一起：**

```
P100 上算一个专家（FP16，M=16）:      90 µs
搬那个专家的权重（FP16，4.00 MiB）:   691 µs   <- 7.7x 算术
搬那个专家的权重（Q4_K，1.81 MiB）:   313 µs   <- 3.4x 算术
```

**主卡每多算一个专家，光搬权重就比算它贵 3.4 倍。**
即使主卡的 FP16 算力无限，PCIe 也回不来。

## 5. 那「主卡多算专家」的账（按实测重算）

主卡算 X 个专家/层，helper 少算 X 个：

- **搬权重的成本**：`X × 313 µs`（量化权重，D2D 常驻的不算），
  或 `X × 691 µs`（FP16 权重）。
- **helper 省下的**：`helper_wait` 13.29 ms/层 ÷ 10240 专家 ≈ **1.30 µs/专家**。

**比值 241 倍（量化）/ 532 倍（FP16）。**
主卡每多算 1 个专家，白搬 313 µs（FP16 是 691 µs），只省下 1.30 µs 的 helper 时间。

**FP16 让这个比值从 241 变成 532 —— 更糟，不是更好。**

## 6. 那 FP16 什么时候才是对的？

只有一种情况：**权重已经在 VRAM 里，且不需要再搬**。

- **keep-resident 的 39 个专家就是这种**（`L.blobs` 里的常驻槽，D2D 拷，0 PCIe）。
  但它们在 prefill 里由主卡的 **int8 MMQ** 算，不走 FP16。
- 把这 39 个改成 FP16 算，**需要先在 VRAM 里存一份 FP16 副本**（+2.21× 显存），
  而收益是「DP4A 2.31× 慢」换成「FP16 慢多少」——
  **实测 P100 的 FP16 GEMM（M=16）0.746 TFLOP/s，而 int8 DP4A 路径的数字没量过，
  这条还没比。** 但注意：主卡算专家要 39 个/层 × 41 层 = 1599 份 FP16 权重
  （1599 × 4 MiB = 6.2 GiB），P100 只有 12 GiB 且现在只放得下 39 个量化版（2.86 GiB）。

## 7. 判断

- **「主卡应该走 FP16」在这台机器上不成立**，三道门各自独立地关着：
  权重量化（没接 FP16 kernel）、权重更大（2.21×）、PCIe 比算术贵 3.4 倍。
- **主卡 FP16 18.7 TF 确实存在，但对专家无用** —— 专家是 int8 量化算的。
  它的 FP16 用在 dense 投影上（attention / shared expert），那部分已经在用。
- **真要吃主卡的 FP16，得让主卡算「不需要搬权重」的活**，也就是已经常驻的那 39 个，
  且要为它们**在 VRAM 里存 FP16 副本**（+2.21× 显存 = +3.4 GiB，P100 装不下）。
  这是**未测的**路径，要先量「int8 MMQ vs FP16 GEMM 算这 39 个」的对比才有结论。
- **prefill 的墙不在主卡的算力**，在 helper 的 PCIe 腿（§
  `2026-10-24-q36-prefill-primary-fp16-review.md` §5）：
  下腿 4 MiB fp32 激活 = 5.18 ms/层，上腿 5.33 MiB fp16 = 6.90 ms/层，
  两段合计 ≈ 12 ms/层，占 forward 26.7 ms 的 45%。**软件能动的只有少传字节。**
